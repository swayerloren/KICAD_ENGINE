# Visual Verification Workflow

## Purpose

This workflow defines how Codex, Claude, and similar agents generate schematic visual evidence without editing KiCad design files or using unsafe GUI automation.

In the full reusable KiCad project pipeline, this workflow provides evidence for `.prompts/kicad_pipeline/02_schematic_visual_closeup_audit.md` and may feed `.prompts/kicad_pipeline/03_schematic_visual_repair.md`. A visual pass alone does not authorize PCB update, placement, routing, copper zones, or fabrication-style output.

## Rule

Visual verification is required before the schematic-to-PCB gate can pass. Full-page exports are not enough; agents must also generate close-up crops for the configured schematic blocks and review each crop.

Automated crop generation is not visual approval. A crop workflow must report `AUTOMATED_CROP_PASS_ONLY` when visual evidence was produced and the limited automated screen did not detect its configured text issues. It must remain `AUTOMATED_CROP_PASS_ONLY` until the rendered full-page image and close-up crops are visually inspected for human readability.

Older outputs that say `Close-up visual review status: PASS` are not acceptable gate evidence unless they also include an explicit rendered-image inspection table. Treat them as stale wording for `AUTOMATED_CROP_PASS_ONLY`.

Future KiCad projects must follow `00_CODEX_START/KICAD_PIPELINE_STARTUP_RULES.md`, `09_ACCURACY_ENGINE/workflows/FULL_KICAD_PROJECT_PIPELINE.md`, and `09_ACCURACY_ENGINE/checklists/FULL_PIPELINE_GATE_CHECKLIST.md` unless the user explicitly approves and logs an exception.

## Safe Control Plane

Use this order:

1. `kicad-cli` SVG/PDF export.
2. `03_TOOLS/scripts/visual/generate_schematic_closeups.py` for crops and `CLOSE_UP_REVIEW.md`.
3. Optional SVG-to-PNG rendering through already-installed local renderers such as Edge, Chrome, ImageMagick, Inkscape, or `rsvg-convert`.
4. GUI screenshots only when CLI-rendered evidence is insufficient.

Do not click, type, save, or otherwise control KiCad GUI for this workflow.

If GUI screenshots or native KiCad state are needed, use `33_KICAD_GUI_AUTOMATION` first. Do not use raw text edits as proof of GUI annotation. If the Eeschema title begins with `*`, treat the schematic as an unsaved GUI state and do not save or annotate by automation without explicit LJ approval and backup.

## Standard Command

```powershell
.\03_TOOLS\kicad\run_schematic_visual_check.ps1 `
  -ProjectRoot ".\04_KICAD_PROJECTS\active\ESP32_CSI_WIFI_NODE" `
  -CreateDefaultConfig
```

Use `-NoFailOnFindings` only for setup/smoke-test report generation. Gate evidence must preserve failures.

## Non-Negotiable Manual Image Review

After running the tool, the agent must open or otherwise visually inspect the rendered full-page PNG and each required crop. The `CLOSE_UP_REVIEW.md` generated by the script is a review worksheet, not the completed review. A completed visual report must add a separate human-readable inspection result for every block.

If the agent cannot inspect the images, write `VISUAL_NOT_VERIFIED` and stop before claiming LJ review readiness.

## Blocking Conditions

Mark visual review incomplete when:

- full-page SVG/PDF evidence is missing
- no crop files are generated
- `CLOSE_UP_REVIEW.md` is missing
- configured default blocks are absent
- the crop does not show the intended circuit block
- visible unannotated references remain
- visible footprint/library/path fields clutter the normal schematic view
- any text, value, reference, or net label overlaps another text item
- any text, value, reference, or net label touches or crosses a wire, pin, symbol body, or power symbol
- power symbols, net labels, and references are stacked or visually touching
- notes are placed inside active circuitry
- notes obscure wires, pins, labels, or symbol bodies
- long review notes or long component values make the block unreadable
- rendered full-page PNG/crops were not visually inspected
- the KiCad GUI or rendered image still visibly shows question-mark references even when file parsing says annotation passed

## Human Readability Requirement

Before reporting `VISUAL_PASS`, the agent must inspect the rendered full-page PNG or screenshot and every required close-up crop. The report must explicitly distinguish:

- `AUTOMATED_CROP_PASS_ONLY`: export/crop/report generation and basic automated screening passed.
- `VISUAL_PASS`: rendered evidence was inspected and no human-readability blockers remain.
- `VISUAL_FAIL`: visible overlap, crowding, note placement, or crop-context blockers remain.
- `VISUAL_NOT_VERIFIED`: rendered evidence was not inspected.

Never return `SCHEMATIC_VISUAL_PASS` from prompt-pack work unless the human-readable inspection row is `VISUAL_PASS`. A script-generated `AUTOMATED_CROP_PASS_ONLY` is still a failed gate for PCB progression.

A schematic cannot be marked `READY_FOR_LJ_VISUAL_REVIEW` if any crop visibly contains overlapping text, values, references, net labels, wires, pins, symbols, or notes inside active circuitry.

## Limitations

- SVG text detection is not OCR.
- SVG text detection can be incomplete or misleading depending on how KiCad exports glyphs. If machine text extraction conflicts with rendered PNG evidence, trust the rendered PNG/crops and classify the visual result conservatively.
- Crops generated from default normalized blocks may need manual coordinate tuning in `visual_blocks.json`.
- Close-up visual review does not prove ERC, DRC, footprint correctness, connector orientation, pinout correctness, or fabrication readiness.
- Close-up visual review is one pipeline gate, not a substitute for annotation checks, electrical audit, BOM lock, footprint/package audit, schematic-to-PCB gate, DRC, or human review.
