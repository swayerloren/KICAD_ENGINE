2. Use or create `_verification/schematic_visual/visual_blocks.json`.
3. Generate full-page SVG/PDF and close-up crops.
4. Open or inspect the rendered full-page PNG and every crop.
5. Create a block-by-block human-readable inspection table.
6. Fail if crops are missing, block names are missing, references are visibly unannotated, or footprint/library/path fields are visible in normal schematic view.
7. Fail if text, values, references, net labels, wires, pins, symbol bodies, power symbols, or review notes overlap, touch, cross, clip, crowd, or make any block unreadable.
8. Fail if a block is using net labels as a shortcut for poor symbol
   orientation, avoidable local wiring, or weak text ownership.
9. Fail if a visually emphasized power, ground, or common-return rail is being
   used as circuitry but has no separate proof that it is a real wire on the
   intended net.
10. Fail if reset/boot or other local control topology is hidden, ambiguous, or
    visually suggests an unsafe power-to-ground short path.
11. Run or review `python 03_TOOLS/scripts/schematic_quality/run_schematic_quality_gate.py --project <ACTIVE_PROJECT_PATH> --no-fail` and do not claim visual readiness if the readability audits still fail.
12. Do not downgrade critical local drafting debt to a soft pass. If local MCU
    support, reset/boot, or emphasized rail presentation is still ambiguous,
    the correct outcome is fail or incomplete review.
13. In the review report, list symbols that still need rotation/flip/reposition
    work, labels that should become wires, labels that are still justified,
    graphic-line versus electrical-wire verification needs, topology sanity
    concerns, and ERC/text/unresolved results when available.
